DNS 泄露是什么？为什么你应该在意？
你访问网站前，浏览器都会先把域名交给 DNS 解析成 IP。如果你挂着代理但 DNS 仍用运营商的明文解析，网站看不到你的真实 IP，但运营商能看到你"正在访问哪个域名"。更糟的是，部分网站会通过你使用的 CDN 节点位置推断你的大致方位——这就是泄露。
发现 DNS 泄露了，怎么修？
最直接的方案：把设备或路由器的 DNS 改为可信的加密服务（DoH/DoT），或在代理客户端里开启"DNS 劫持 / 虚拟 DNS（fake-IP）"模式，让所有解析都走代理隧道完成。
为什么用了代理，DNS 还是会泄露？
常见原因是"分流规则只接管了 TCP 流量，没接管 UDP 53 的 DNS 查询"；或者浏览器开启了自己的 DoH，绕过了代理的 DNS 设置；也可能是系统多网卡（IPv4 走代理、IPv6 直连）导致的旁路泄露。
DoH、DoT、普通 DNS 有什么区别？哪个最安全？
普通 DNS 是明文 UDP 53，链路上任何节点都能看到并篡改；DoT（853 端口）与 DoH（443 端口）都是 TLS 加密，DoH 因为与网页流量同端口、更难被识别和封锁。安全性：DoH ≥ DoT ≫ 普通 DNS。
WebRTC 泄露又是什么鬼？
WebRTC 为了音视频通话质量，会通过 STUN 协议直接用 UDP 探测你的公网地址，这个过程可以绕过仅代理 HTTP/S 流量的方案。可以到「WebRTC」页面做一次 UDP 快检。
