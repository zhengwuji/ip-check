Claude 实时服务状态怎么查？
Anthropic 官方状态页实时汇总 API 与网页的可用性，本站「服务状态」页面会自动聚合显示。如果你在「可用性检测」里看到异常，可先去状态页确认是否为官方故障，再排查本地网络。
家宽、机房、原生 IP 有什么区别？
家宽（ISP）IP 由运营商分配给家庭用户，风控信任度最高；机房（Hosting）IP 由数据中心持有，常被批量使用，风控更敏感；"原生"指 IP 归属地与注册地一致。本页的信任评分就是基于这三者计算。
时区与语言不一致会有影响吗？
出口 IP 在美国、但浏览器时区是 UTC+8、语言是中文，这种组合是 AI 风控的常见信号之一。它本身不直接封号，但会提高整体风险评分。建议让浏览器环境与出口 IP 尽量一致。
WebRTC 泄露为什么要查？
WebRTC 通过 UDP 直接探测公网地址，可能绕过仅代理 HTTP/S 的方案暴露真实 IP。本页的「WEBRTC UDP 泄露检测」是快速版，完整版请到「WebRTC」页面。
DNS 泄露为什么也要查？
明文 DNS 查询会把你访问的域名暴露给本地运营商，也能被用于推断真实位置。建议用「DNS泄露」页面的唯一子域名检测验证你的 DNS 是否已加密。
为什么本次检测 Cloudflare 出口获取失败？
「CLOUDFLARE 出口IP」取自 1.1.1.1 的 trace 接口。部分代理规则不放行 1.1.1.1，会显示获取失败——这不代表你的网络有问题，CLAUDE 出口才是本页的核心数据。
被风控后的自查清单
① 看本页信任评分与安全检测；② 确认出口地区受支持；③ 检查时区/语言是否与出口一致；④ 查 DNS 与 UDP 是否泄露真实位置；⑤ 更换更纯净的出口后再试。
IPv6 环境访问 AI 服务要注意什么？
如果你的网络同时有 IPv4 和 IPv6，浏览器可能优先走 IPv6 出口。若代理只接管 IPv4，真实 IPv6 地址就会泄露。可在「WebRTC」页面观察候选地址中是否有你本地 IPv6。
Claude 客户端会读取我的时区吗？
据公开的逆向研究，Claude 桌面与终端客户端在连接时会读取操作系统时区等本机信息。网页拿不到客户端能读的全部数据，但关键信号一致——本页读取的正是同一个系统时区，并叠加语言、字体等指纹加权评分。
怎样降低「中国用户特征」得分？
最有效的是切断时区锚定：把系统（或浏览器）时区改为同样 UTC+8 但不属于中国大陆的时区，例如 Asia/Singapore，语言列表里的中文条目也会显著拉高得分，可按需精简。系统级改动优先于浏览器插件伪装，因为客户端读的是操作系统值。
