WebRTC 泄露是怎么回事？
WebRTC 建立连接时要先弄清"我在公网上的地址是什么"，于是向 STUN 服务器发 UDP 包询问。这个询问不经过 HTTP 代理，如果代理方案没接管 UDP，STUN 就会看到你的真实宽带 IP。
STUN 和 UDP 是什么？
UDP 是无连接的传输协议，音视频通话多用它来降低延迟；STUN 是帮内网设备弄清自己"公网门牌号"的辅助协议。两者组合让通话更快，也让泄露更隐蔽。
发现泄露了，怎么修？
优先方案：使用全局/TUN 模式的代理客户端，或在浏览器安装 WebRTC 控制扩展并禁用非中继候选；企业环境可在防火墙层拦截 UDP 3478/19302 等 STUN 端口。
多个出口 IP？不一定是 WebRTC 泄露
host 候选里的 192.168.x.x / 10.x.x.x 只是局域网地址，mDNS（….local）更是浏览器的隐私保护。真正需要关注的是 srflx（公网）候选与 HTTP 出口是否一致。
除了 WebRTC，DNS 泄露同样危险
DNS 明文查询会暴露你访问的域名，也能被用来推断位置。建议做完本页检测后，再到「DNS泄露」页面跑一轮唯一子域名检测。
为什么代理模式和 TUN 模式检测结果不同
普通代理模式只接管浏览器发出的 TCP；TUN/增强模式在系统层接管全部流量（含 UDP），所以 STUN 探测也会走代理出口，两种模式下的 srflx 地址会不同。
