为什么要做分流出口检测？
代理客户端的分流规则决定了「哪个网站走哪条线路」。规则写完并不等于生效：可能被域名列表更新覆盖，也可能被通配规则抢先匹配。逐一读取每个站点实际看到的出口 IP，是验证规则是否生效最直接的办法——比如 claude.ai 应走美国专线、国内站点应直连，一看便知。
检测原理是什么？
你的浏览器直接向每个目标站点发起一次只读请求，目标站点在响应里回显它看到的来源地址（Cloudflare 系站点为公开的 cdn-cgi/trace 接口，允许任何网页跨域读取）。因为请求由浏览器发出，它经过的代理链路与正常访问完全一致，看到的就是真实分流结果。DNS 出口通过唯一子域名让本机解析一次来探测；WebRTC 出口通过 STUN 获取 UDP 映射地址。
为什么没有国内网站？
国内站点没有开放跨域读取的 IP 回显接口，浏览器拿到响应也无法读取内容，所以本页暂不含国内目标。想验证国内直连，可以用「网络连通」页面的国内站点延迟测试，或对比 api.ipify.org（直连参考）与其他目标的差异。
所有出口都一样是正常的吗？
分两种情况：如果你只用全局代理，所有站点出口一致是正常的；如果你配置了分流规则，所有站点仍然同一个出口，说明规则没有命中——常见原因是客户端没有开启对应模式、订阅里没有对应域名列表，或规则被更靠前的通配条目拦截。
DNS 出口和站点出口不一致说明什么？
站点出口是 HTTP/HTTPS 流量的走向，DNS 出口是域名解析请求的走向。两者可以合法地不同（比如开启 fake-IP 后解析由代理端完成）；但如果 DNS 出口显示为你本机宽带运营商的地址，而站点出口是代理，说明 DNS 在本地明文解析，存在 DNS 泄露，可到「DNS泄露」页面做深度检测。
本页会记录我的 IP 吗？
探测请求由你的浏览器直接发往目标站点，本站服务器无法感知；唯一的本站请求是批量归属地查询，只包含待查询的 IP 列表，不与你的会话关联保存。
